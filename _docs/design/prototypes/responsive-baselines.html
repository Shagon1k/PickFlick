Responsive contract · current prototypes

One product, four clear modes.

PickFlick uses four canonical responsive modes. Layouts remain fluid inside each mode; new one-off viewport thresholds are not part of the design contract.

S · <576M · 768L · 1024XL · 1400+

Canonical modes

These are the only viewport modes used for new implementation work. The `576–767px` interval keeps the S composition and grows fluidly toward M.

S · <576pxSmallCompact mobile composition, stacked content, fixed mobile product navigation and minimum 44px touch targets.
M · ≥768pxMediumTablet composition with broader regions and denser rows. Navigation remains compact until the desktop shell becomes useful.
L · ≥1024pxLargeDesktop header, sidebars, tabs and primary multi-column layouts become canonical.
XL · ≥1400pxExtra largeFull desktop composition with restrained max-width content; only cinematic canvas effects extend to viewport edges.

Non-negotiable rules

These constraints make responsive implementation testable rather than subjective.

No horizontal page scroll

Verify the four representative widths: 390, 768, 1024 and 1440. Tables and rails may scroll inside clearly bounded containers.

Mobile is recomposed

Desktop sidebars, tabs and dense rows are replaced by mobile navigation and prioritized content—not merely scaled down.

Touch targets remain usable

Interactive controls stay at least 44px in the product shell even when their visual glyphs are smaller.

Wide canvas stays restrained

Core content remains inside the 1120px container; only cinematic canvas effects may extend to the viewport edges.
